## 2026-10-17 | 固化 AppKit 原生 HUD 悬浮提示与自动化网页报告能力至 MCP 服务端

- **问题核心**：用户希望将 ChatGPT 临时编写的 AppKit 原生桌面悬浮提示（`evenswiss_tip`）及查看网页版详情链路，正式固化为 MCP 核心服务能力，使所有 AI 都能在完成自动化任务后主动通知并联动浏览器。
- **方向信号**：
  - **核心现象/痛点**：AI 执行文件整理、重命名、数据处理等批处理任务时缺乏物理桌面视觉反馈；原有 Swift 脚本作为散落文件存在，且部分子目录（如 `Plasma_261006`）因目录缺少 `w` 写权限导致重命名误报“权限受限”。
  - **机制与原理**：
    - 将 AppKit 原生毛玻璃悬浮窗程序（`desktop_tip`）支持 `--json-base64`，彻底规避终端引号转义问题，置于系统 PATH；
    - 在 `coding_tools_mcp` 正式注册 `show_desktop_tip` 工具，允许传入 `title`、`message`、`action_url` 或直接传入 `html_content`（由服务端自动持久化为离线 HTML 报告并一键挂载）；
    - 修复了 `01_Evenswiss` 中只读目录权限问题（`chmod u+w`），消除了文件写入假性权限屏障。
  - **认知转变**：MCP 不仅是后台被动的只读/文件工具，更是可直接参与前端物理会话交互的 HUD（抬头显示）系统；通过将交互通知与离线报告闭环打通，AI 的交付物直接变成用户桌面“可见即可点击”的富媒体体验。
- **决策与影响**：
  - 固化 `show_desktop_tip`、`list_project_tree`、`read_project_document` 三项能力至 `coding_tools_mcp`；
  - 编译并在 Mac 安装原生 94KB x86_64 二进制 `desktop_tip`，LaunchAgent 已平滑热载生效；
  - 修复 `Plasma_261006` 目录权限，更新 `AGENTS.md` 交互协议。→ [实现日志](../_dev_log/2026-10-17_mcp-native-desktop-tip-hud.md)

## 2026-10-17 | 能力描述必须来自真实路径策略并覆盖握手提示

- **问题核心**：修正 macbook-betty MCP 的能力描述，避免网页版将默认工作区误判为真实访问边界。
- **方向信号**：
  - **核心现象/痛点**：工具说明、初始化握手和实际路径解析不一致；仅修某个工具说明不足以消除矛盾。
  - **机制与原理**：将工作区锚点、路径 confinement、执行权限模式和系统 ACL 分开，自报读取实际解析器状态。
  - **认知转变**：能力描述不是授权开关；服务端描述需随实例变化，且文本、结构化结果、旧版握手与新版发现必须一致。
- **决策与影响**：
  - 仓库补齐动态能力自报与 8 项回归；MacBook 保留既有路径行为并备份后部署，原 MCP 重连实测成功。→ [实现日志](../_dev_log/2026-10-17_mcp-filesystem-capability-descriptions.md)

## 2026-10-16 | 工作区路径提示不能替代实际访问策略

- **问题核心**：网页版称 MCP 无权访问桌面，是否只是按工作区提示作保守判断，是否需要更改。
- **方向信号**：
  - **核心现象/痛点**：同一远程 MCP 的绝对路径及大小写不同的 home 简写均实测成功，工具描述仍称仅在配置工作区内列目录。
  - **机制与原理**：工作区锚点、路径 confinement、执行权限模式、主机文件 ACL 是不同层；模型说明不是服务端拒绝的证据。
  - **认知转变**：先依据只读探测与结构化错误判断，再校准 metadata，不能通过盲目放宽权限解决表述误导。
- **决策与影响**：
  - 当前不改服务权限；建议暴露有效文件访问策略并令描述与之对齐。缺网页版原始错误，保留历史原因的不确定性。→ [实现日志](../_dev_log/2026-10-16_macbook-mcp-access-probe.md)
